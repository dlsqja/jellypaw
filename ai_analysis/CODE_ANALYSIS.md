# analyze_corrected_improved.py 코드 분석

## 📋 전체 개요

이 스크립트는 **소변검사 스틱 이미지를 AI로 분석**하여 10개 검사 항목의 결과를 자동으로 판독하는 시스템입니다.

**핵심 원리**:

1. 이미지에서 소변검사 스틱의 패드 위치를 YOLO로 탐지
2. 각 패드의 색상을 LAB 색공간으로 추출
3. 이미지 내 기준 색상표와 비교하여 가장 유사한 값 매칭
4. Delta E(색상 차이)를 계산하여 진단 결과 도출

---

## 🔄 전체 처리 플로우

```
[이미지 입력]
    ↓
[1단계] 투시 변환 (4개 마커 기반)
    ↓
[2단계] 색상 보정 계수 계산 (회색 영역 기준)
    ↓
[3단계] YOLO 모델로 10개 패드 탐지
    ↓
[4단계] 기준 색상표 추출 (YOLO 패드 위치 기반)
    ↓
[5단계] 패드 색상 추출 및 보정
    ↓
[6단계] Delta E 계산 및 진단
    ↓
[7단계] 프론트엔드용 JSON 응답 생성
```

## 📦 주요 함수별 상세 분석

### 1. 데이터 로드 함수

#### `load_digital_reference_data()` (50-63줄)

- **역할**: 디지털 기준 색상표 데이터 로드
- **파일**: `digital_reference_colors_hex.json`
- **내용**: 각 검사 항목별 이상적인 색상 값 (HEX, RGB, LAB) 및 진단 메타데이터
- **용도**: 매칭된 값의 `result`, `is_normal`, `severity` 정보 추출

#### `load_disease_info_data()` (33-45줄)

- **역할**: 양성 시 의심 질환 정보 로드
- **파일**: `urine_test_with_diseases.json`
- **내용**: 각 검사 항목별 양성/비정상 시 의심되는 질환 목록
- **용도**: 프론트엔드에 의심 질환 정보 제공

### 2. 이미지 전처리 함수

#### `perform_warp_perspective()` (90-137줄)

**목적**: 카메라 각도에 관계없이 이미지를 정규화

**처리 과정**:

1. **그레이스케일 변환** (94줄)

   - 컬러 이미지를 회색조로 변환

2. **이진화** (95줄)

   - `THRESH_BINARY_INV`: 검정색 마커를 흰색으로, 배경을 검정색으로
   - 임계값 50 사용

3. **컨투어 찾기** (98줄)

   - 가장 큰 4개의 컨투어 선택 (마커 4개)

4. **마커 중심 좌표 계산** (101-108줄)

   - 각 마커의 무게중심(centroid) 계산
   - `moments` 함수 사용

5. **마커 좌표 정렬** (115-121줄)

   - Y좌표 기준으로 상단/하단 분리
   - X좌표 기준으로 좌/우 정렬
   - 최종 순서: [좌상, 우상, 우하, 좌하]

6. **투시 변환 실행** (132-134줄)
   - `getPerspectiveTransform`: 변환 행렬 계산
   - `warpPerspective`: 실제 변환 수행
   - 목표 크기: 600x1000 픽셀

**결과**: 기울어진 이미지를 정면에서 본 것처럼 정규화

---

### 3. 색상 보정 함수

#### `extract_gray_reference()` (336-351줄)

**목적**: 회색 직사각형 영역에서 기준 색상 추출

- **위치**: (86, 15) ~ (122, 526) 고정 좌표
- **추출**: LAB 색공간으로 변환 후 평균값 계산
- **이상적인 값**: L=128, A=128, B=128 (중간 회색)

#### `calculate_color_correction()` (353-367줄)

**목적**: 조명/환경 차이를 보정하기 위한 계수 계산

**계산 방식**:

- **L 보정**: `128.0 / measured_gray[0]` (곱셈)
- **A 보정**: `128.0 - measured_gray[1]` (덧셈)
- **B 보정**: `128.0 - measured_gray[2]` (덧셈)

**예시**:

- 측정된 회색: L=207.42 → 보정 계수: 128/207.42 = 0.617
- 모든 색상에 이 계수를 적용하여 조명 차이 보정

#### `apply_color_correction()` (369-378줄)

**목적**: LAB 색상에 보정 계수 적용

```python
L_corrected = L * L_correction      # 곱셈
A_corrected = A + A_correction      # 덧셈
B_corrected = B + B_correction      # 덧셈
```

**중요**: 기준 색상표와 패드 색상 모두에 동일한 보정 적용 (698-705줄)

### 4. YOLO 패드 탐지 함수

#### YOLO 모델 로드 (622-626줄)

- **모델 파일**: `weights/best.pt`
- **역할**: 소변검사 스틱의 10개 패드 위치 탐지

#### YOLO 추론 및 결과 처리 (628-677줄)

**처리 과정**:

1. **YOLO 추론 실행** (629줄)

   - 투시 변환된 이미지에서 패드 탐지

2. **좌표 변환** (635-641줄)

   - YOLO 정규화 좌표 (0~1) → 픽셀 좌표 변환
   - `normalize_to_pixel_coords()` 함수 사용

3. **Y좌표 기준 정렬** (654줄)

   - 위에서 아래로 정렬 (패드 순서 고정)

4. **클래스 이름 재할당** (656-677줄)
   - YOLO가 잘못 탐지해도 순서대로 재할당
   - 예: `pad_Bilirubin` → `pad_Glucose` (순서대로)

**탐지 결과 구조**:

```python
{
    'class': 'pad_Urobilinogen',
    'box_pixel': [x_min, y_min, x_max, y_max],
    'confidence': 0.7447,
    'center_y': 63
}
```

### 5. 기준 색상표 추출 함수

#### `extract_reference_colors_from_yolo()` (142-331줄)

**목적**: 이미지 내 기준 색상표에서 색상 추출

**핵심 원리**:

- YOLO가 찾은 패드의 **Y좌표**를 기준으로 같은 높이의 기준 색상표 추출
- 패드 중심 X좌표 + **X 오프셋** = 기준 색상표 위치

**처리 과정**:

1. **패드 위치 정보 수집** (158-178줄)

   - 각 패드의 중심 좌표 (X, Y) 저장

2. **기준 색상표 위치 계산** (184-256줄)

   - `reference_offsets`: 각 검사 항목별 기준 색상표의 상대 위치
   - 예: Urobilinogen의 "4" 값은 패드 중심에서 오른쪽으로 90픽셀

3. **색상 추출** (281-324줄)
   - **외곽 박스**: 50x50 픽셀 (디버깅용, 파란색 사각형)
   - **실제 추출 영역**: 중앙 25x25 픽셀 (배경 제거)
   - LAB 색공간으로 변환 후 평균값 계산

**X 오프셋 예시**:

```python
"Urobilinogen": [
    {"value": "0.1", "x_offset": -130},  # 왼쪽 2번째
    {"value": "2", "x_offset": -75},     # 왼쪽 1번째
    {"value": "4", "x_offset": 90},      # 오른쪽 1번째
]
```

### 6. 색상 추출 함수

#### `extract_lab_color()` (383-411줄)

**목적**: 패드 영역에서 색상 추출

**처리 방식**:

- **중앙 70% 영역만 사용** (배경 색상 제거)
- BGR → LAB 색공간 변환
- 평균 LAB 값 계산

**LAB 색공간 선택 이유**:

- 인간의 색상 인지와 유사
- Delta E 계산에 적합

### 7. 색상 비교 및 진단 함수

#### `calculate_delta_e()` (416-424줄)

**목적**: 두 색상 간의 차이를 수치화

**공식 (CIE76)**:

```
Delta E = √[(L1-L2)² + (A1-A2)² + (B1-B2)²]
```

**해석**:

- 0 ~ 5: 거의 동일
- 5 ~ 15: 매우 유사
- 15 ~ 30: 유사
- 30 ~ 40: 다소 다름
- 40 이상: 매우 다름

#### `perform_diagnosis()` (426-478줄)

**목적**: 측정된 패드 색상과 기준 색상표 비교하여 진단

**처리 과정**:

1. **모든 기준 색상과 비교** (442-448줄)

   - 각 기준 색상과 Delta E 계산
   - 가장 작은 Delta E 값을 가진 색상 선택

2. **근사치 판단** (450-458줄)

   - Delta E < 20: `confidence: "high"`
   - Delta E 20~40: `confidence: "medium"`
   - Delta E >= 40: `confidence: "low"`, `is_approximate: false`

3. **메타데이터 추출** (460줄)
   - `get_metadata_from_digital_reference()` 호출
   - `result`, `is_normal`, `severity` 정보 가져오기

**반환 구조**:

```python
{
    "matched_value": "2",
    "delta_e": 15.31,
    "result": "negative",
    "is_normal": true,
    "severity": "N/A",
    "is_approximate": true,
    "confidence": "high"
}
```

## 🎯 핵심 알고리즘 원리

### 1. 투시 변환 (Perspective Transform)

**문제**: 카메라 각도에 따라 이미지가 기울어짐
**해결**: 4개 마커를 기준으로 정면 뷰로 변환
**수학**: 호모그래피 변환 행렬 사용

### 2. 색상 보정 (Color Correction)

**문제**: 조명/환경에 따라 색상이 달라짐
**해결**: 회색 영역을 기준으로 보정 계수 계산
**원리**:

- 이상적인 회색: LAB(128, 128, 128)
- 측정된 회색: LAB(207, 128, 127)
- 보정 계수: L=0.617, A=0.061, B=0.691
- 모든 색상에 동일 적용

### 3. 기준 색상표 동적 추출

**문제**: 이미지마다 기준 색상표 위치가 다를 수 있음
**해결**: YOLO가 찾은 패드 위치를 기준으로 상대 위치 계산
**원리**:

- 패드 중심 Y좌표 = 기준 색상표 Y좌표
- 패드 중심 X좌표 + 오프셋 = 기준 색상표 X좌표

### 4. Delta E 색상 비교

**문제**: RGB는 인간의 색상 인지와 다름
**해결**: LAB 색공간 사용 (인간의 색상 인지와 유사)
**원리**:

- L: 밝기 (Lightness)
- A: 녹색-빨강 축
- B: 파랑-노랑 축
- Delta E: 유클리드 거리로 색상 차이 계산

### 5. 근사치 판단

**목적**: 신뢰도가 낮은 결과 필터링
**임계값**:

- Delta E < 20: 높은 신뢰도
- Delta E 20~40: 중간 신뢰도
- Delta E >= 40: 낮은 신뢰도 (경고)

## 🔑 핵심 설계 포인트

### 1. 기준 색상표를 이미지에서 추출

- **장점**: 이미지마다 다른 조명/환경에 자동 적응
- **단점**: 기준 색상표 위치가 정확해야 함

### 2. 동일한 보정 적용

- 기준 색상표와 패드 색상 모두에 동일한 보정 계수 적용
- 보정 전 값끼리 비교하면 불일치 발생

### 3. Y좌표 기반 순서 보장

- YOLO가 잘못 탐지해도 순서대로 재할당
- 패드 순서가 항상 동일하다는 가정

### 4. 중앙 영역만 추출

- 배경 색상 포함 최소화
- 패드: 중앙 70%, 기준 색상표: 중앙 25x25 픽셀

## ⚠️ 주의사항 및 한계

### 1. 기준 색상표 위치 의존성

- X 오프셋 값이 실제 이미지와 일치해야 함
- 기준 색상표 위치가 달라지면 오프셋 재조정 필요

### 2. 회색 영역 좌표 고정

- (86, 15) ~ (122, 526) 좌표가 실제 회색 영역과 일치해야 함
- 다른 이미지 형식에서는 좌표 수정 필요

### 3. YOLO 모델 정확도

- 모델이 패드를 정확히 탐지해야 함
- 탐지 실패 시 순서 기반 재할당으로 보완

### 4. Delta E 임계값

- 현재 40을 기준으로 근사치 판단
- 필요에 따라 조정 가능
